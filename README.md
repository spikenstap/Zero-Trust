# Zero Trust Medical

Учебный MVP: один FastAPI-процесс, SQLite, статический HTML / CSS / vanilla JS. Все пять пациентов и медицинские записи вымышленные. Каждый запрос `/api/*` проходит проверку токена, лимита и политики и попадает в аудит. Это демонстрация принципов Zero Trust, не система для реальных медицинских данных.

## Быстрый запуск: Docker

Нужен запущенный Docker Desktop / Docker Engine с Compose v2. Из папки проекта:

```sh
docker compose up
```

Откройте http://localhost:8000. При первом запуске образ собирается автоматически. Уникальные секреты генерируются в `/config/.env` внутри постоянного тома `demo-config`; БД — в отдельном томе `demo-data`. На следующих запусках ключи сохраняются. Криптографические ключи не встроены в образ; общий учебный пароль `demo123` намеренно публичен. `.env.example` описывает параметры. Compose публикует порт только на `127.0.0.1`.

Остановить: `docker compose down`. После изменения исходников: `docker compose up --build`. Команда `docker compose down -v` удалит оба тома, включая ключи и учебные данные. Обычно для повторного показа достаточно кнопки «Сбросить демо».

## Локальный запуск: Python 3.11+

Windows PowerShell:

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
python scripts/init_env.py
uvicorn app.main:app
```

Linux / macOS:

```sh
python3 -m venv .venv
. .venv/bin/activate
python -m pip install -r requirements.txt
python scripts/init_env.py
uvicorn app.main:app
```

Откройте http://127.0.0.1:8000. Если PowerShell запрещает активацию, используйте `.\.venv\Scripts\python.exe -m pip ...` и `.\.venv\Scripts\python.exe -m uvicorn app.main:app`. Скрипт `init_env.py` не перезаписывает существующий `.env`. Запускайте команды из корня проекта. Для разработки можно добавить `--reload`; несколько workers не поддерживаются демо-лимитером.

Секреты читаются из `.env`, путь можно переопределить `ENV_FILE`. Переменные окружения имеют приоритет. JWT_SECRET — случайная строка не короче 32 символов; FERNET_KEY — URL-safe Base64 от 32 случайных байт. Невалидные / незаданные ключи блокируют запуск. Не меняйте ключ Fernet при сохранении БД: старые записи станут нечитаемыми.

## Демо за 3 минуты

1. **0:00–0:30.** Нажмите «Подключить admin» в журнале. Затем выберите Айдара. Видны только пациенты **1, 2, 5**. Откройте Дану: диагноз расшифрован. Раскройте «Посмотреть JWT»: токен действует 15 минут.
2. **0:30–1:00.** Выберите медсестру: видны все 5 пациентов, но диагноз и заметки скрыты. Выберите Дану: доступна только карта **1**. Выберите администратора: список пациентов возвращает **403**, журнал остаётся доступным.
3. **1:00–2:00.** В панели атак нажмите по очереди «Запрос без токена» (**401**), «Подделанный токен» (**401**), «Чужая карта × 3» (три **403**, третий отказ помечен), «Ночной доступ» (**200**, оранжевая аномалия). Результат содержит ID аудита; соответствующие строки отмечены синей линией. Атаки выполняются от `doctor_aidar` в отдельной сессии; чужая карта — **3**, врач Сара.
4. **2:00–2:30.** Нажмите «Спам запросами»: 15 запросов, после исчерпания бюджета — **429** и аномалия. Уже выполненные запросы Айдара тоже учитываются. Интерфейс выжидает 10 секунд перед следующей атакой; перевход не обходит лимит. Переключатель «Имитировать ночь» добавляет ночной признак к вашим последующим запросам карт.
5. **2:30–3:00.** Покажите в журнале пользователя, роль, действие, код, причину и аномалии. Нажмите «Сбросить демо» и подтвердите: карты восстановлены, журнал содержит только событие сброса, все прежние JWT отозваны. Для нового показа войдите снова и подключите наблюдателя.

В таблице указано реальное время события. Имитация ночи не подменяет часы: в аудите сохраняется `simulated_night=true`. Ночной интервал — **[00:00, 05:00)** в `APP_TIMEZONE` (по умолчанию Asia/Qyzylorda). В это время даже разрешённый запрос считается подозрительным.

## Пользователи и политика

У всех пароль `demo123`, хеши PBKDF2-SHA256 с индивидуальной солью и 290 000 итераций через passlib.

| Логин | Роль | Доступ |
|---|---|---|
| doctor_aidar | doctor | Карты 1, 2, 5 |
| doctor_sara | doctor | Карты 3, 4 |
| nurse_aigul | nurse | Общие поля всех карт; диагноз и заметки замаскированы |
| patient_dana | patient | Только собственная карта 1 |
| admin | admin | Аудит и сброс; медицинские данные запрещены |

Список пациентов не включает диагноз и заметки. Полная карта расшифровывается только после проверки политики. Для медсестры расшифровка вообще не вызывается. Ответ на запрос отсутствующей / чужой карты не раскрывает существование пациента.

Администратор-наблюдатель — **отдельный явно подключаемый JWT**, не обход авторизации. Он позволяет показывать аудит одновременно с действиями врача. Журнал не выдаётся врачу или пациенту. Оба токена хранятся только в памяти страницы; обновление страницы завершает клиентские сессии. Выход из текущей роли не отключает отдельного наблюдателя; для него есть кнопка «Отключить admin». Токены разных сессий одного пользователя разделяют общий лимит.

## API

| Метод | Путь | Назначение |
|---|---|---|
| POST | /auth/login | JSON `{ "username": "doctor_aidar", "password": "demo123" }` → `access_token`, `token_type`, `expires_in`, `user` |
| GET | /api/me | Текущий пользователь |
| GET | /api/patients | Отфильтрованный список |
| GET | /api/patients/{id} | Карта по политике |
| GET | /api/audit?limit=100 | Только admin; `limit` от 1 до 500 |
| POST | /api/demo/reset | Только admin; восстановление seed, отзыв токенов и очистка истории |
| GET | /health | Публичная проверка готовности |

Все `/api/*` требуют `Authorization: Bearer <JWT>`. Публичны только страница, статические файлы, `/auth/login` и `/health`. Неизвестные API-действия и неподдерживаемые методы по умолчанию запрещены. Документация OpenAPI отключена для компактности демо.

JWT использует фиксированный HS256, `sub`, `role`, `iat`, `exp`, `ver`. `ver` — версия сессий пользователя: меняется при сбросе. Сервер проверяет подпись, срок, обязательные claims, существование пользователя, роль и версию по БД. Из невалидного JWT не извлекается доверенная личность: аудит записывает `anonymous`.

Ответы API содержат `X-Audit-ID`, `X-Request-ID`, `X-Audit-Suspicious`; 429 также содержит `Retry-After`. Тело отказа: `detail`, `audit_id`, `request_id`, `suspicious`. Для имитации ночи: `X-Demo-Night: 1`. Это явно учебный переключатель; отключить детектор реальной ночи им нельзя.

## Как устроен шлюз

```text
Браузер → Gateway → проверка JWT и пользователя → лимит → authorize()
                                                      ├─ deny → аудит → 401 / 403 / 429
                                                      └─ allow → аудит → обработчик → ответ
```

Политика задаётся функцией `authorize(user, action, resource) -> Decision(allow, reason)`. Она вызывается для маршрута и для каждой возвращаемой записи; обработчики повторяют проверку через `require_access` перед чтением или изменением данных. Шлюз использует путь ASGI, совпадающий с маршрутизатором; заголовок Host не влияет на выбор политики. Запись решения выполняется до передачи разрешённого запроса обработчику. Ошибка записи аудита не позволяет выполнить обработчик. Для ошибки обработчика журнал уточняет HTTP-статус и пересчитывает серию отказов, включая ошибки 422 и 500. Проверки и обработка API сериализованы в одном процессе: это сохраняет порядок отказов, атомарность лимитера и согласованность со сбросом. Восстановление данных и запись события сброса выполняются одной транзакцией SQLite.

Детектор смотрит два предыдущих события того же аутентифицированного пользователя: третий и последующие последовательные `deny` помечаются; `allow` обрывает серию. Невалидные токены не приписываются заявленному `sub`, а три разных анонимных запроса не объединяются в одного пользователя. Любой 429 и любой ночной запрос помечаются отдельно. Состояние серии хранится в аудите, лимит — в памяти процесса с монотонными часами.

Чтение `/api/audit` тоже проверяется, ограничивается и логируется. Поэтому при автообновлении появляются события `audit.read`; их видно в таблице и счётчиках. Счётчики отражают последние 100 событий, а не всю историю. При 429 наблюдатель ждёт `Retry-After`, при истечении JWT отключается. Обновление можно поставить на паузу.

## Структура

```text
app/
  main.py       # сборка, lifespan, заголовки, статические файлы и reset
  config.py     # .env и проверка секретов
  db.py         # SQLite и сессии SQLAlchemy
  models.py     # User, Patient, AuditEvent
  seed.py       # вымышленные данные и хеширование паролей
  crypto.py     # шифрование Fernet
  auth.py       # логин, JWT, /api/me
  policy.py     # least privilege и deny by default
  gateway.py    # JWT → limiter → policy → audit
  patients.py   # фильтрация и сериализация карт
  audit.py      # события, аномалии, журнал
static/
  index.html
  app.js
  style.css
tests/
scripts/init_env.py
Dockerfile
compose.yaml
.env.example
requirements.txt
```

## Тесты

```sh
python -m pytest -q
```

pytest + FastAPI TestClient (httpx). Каждая проверка получает отдельную временную SQLite и случайные ключи; реальные `.env` / БД не используются. Обязательные 11 сценариев покрыты в `tests/test_security.py`. Дополнительно проверяются границы ночного времени, смена роли в подписанном JWT, восстановление окна лимита, общий бюджет для разных токенов, невозможность расшифровки у медсестры, сброс серии отказов, неизвестные маршруты и отзыв JWT после reset.

## Границы прототипа и развитие

Известные демо-пароли, открытая форма выбора пользователей и имитация ночи сделаны для защиты проекта. Не публикуйте этот режим с реальными данными. Login не является промышленной системой IAM: нет регистрации, MFA, блокировки перебора и восстановления пароля. JWT действует до 15 минут; выход очищает его в браузере, а глобальный отзыв происходит при reset. Fernet защищает поля БД, но сервер, располагающий ключом, может их прочитать. Общие поля остаются открытыми.

Лимитер рассчитан на **один worker**, без распределённого состояния. SQLite-аудит не является неизменяемым: администратор демо может сбросить журнал. Не реализованы TLS внутри приложения, резервные копии, ротация ключей, неизменяемое внешнее хранилище аудита и управление доступом к секретам уровня production. Сериализация API подходит для небольшой демонстрации, не для нагрузки. Тяжёлые проверки паролей выполняются в том же процессе. Объём журнала ограничен только сбросом демо; чтение ограничено 500 строками.

Модули можно выделить позже: `auth.py` — отдельный сервис идентификации с проверкой issuer/audience и JWKS; `policy.py` — сервис решений; `patients.py` — сервис карт; `audit.py` — отдельный приёмник событий. Gateway проверяет каждую границу, а сервис карт повторно проверяет разрешение и идентичность вызывающего сервиса. Потребуются аутентификация сервисов, защищённый транспорт, общий атомарный лимитер, надёжная доставка событий и управление ключами. В этом MVP все эти границы остаются модулями одного приложения.
